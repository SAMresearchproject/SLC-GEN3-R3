## Request

I request that the d_ref work performed "in response to" the chat-history
reference be treated as unnecessary and VOID for record-control purposes.

The reason is not that the underlying d_ref question was unimportant. The reason
is that the work chain was initiated and escalated under a defective source
picture:

1. It treated the `d_ref = 1` reference as if it were only a chat-history item.
2. It used material outside the repo as the practical trigger for audit and
   downgrade pressure.
3. It failed to disclose that the same relevant normalized convention was
   already present inside the repo in CR004_PRECOMMIT.
4. It allowed a redacted CR013 input package to transform CR004's explicit
   normalized unit convention into an unknown for the DERIVER.
5. It then allowed context-limited underdetermination to drive broader audit and
   downgrade pressure.

Because those operational failures affected the premise, the chat-reference-
driven demand chain should not remain controlling.

## Scope Of Void

The requested VOID disposition applies to the work chain whose purpose was to
respond to, audit, downgrade, or demand derivation because of the chat-history
`d_ref = 1` reference as though that reference were the only controlling source.

This includes any framing that says, implies, or depends on:

- `d_ref = 1` existed only in chat history;
- the repo did not contain the relevant normalized convention;
- audits or downgrades were necessary because no repo-local source existed for
  the normalized `d_ref = 1` convention;
- CR013 DERIVER underdetermination, produced from the redacted package, globally
  refuted or displaced CR004's normalized convention.

This VOID disposition does not erase the historical artifacts. It marks the
chat-reference-driven premise as non-controlling.

## Controlling Source-Bounded Position

The current record should distinguish the following claims:

1. `d_ref_norm = 1` is source-supported by CR004_PRECOMMIT and CR004's
   normalized distance-coupling test record.
2. Chat history may be cited as origin/provenance support, but it is not the
   sole source and should not be cited ahead of CR004 for the repository record.
3. Absolute `d_ref_abs` in SI meters remains not derived from CR004 alone.
4. CR013 DERIVER underdetermination remains valid only for the redacted context
   it was given and for absolute SI length questions.
5. The blind/source-bounded d_ref derivation is the cleanest best-effort repair
   of the normalization question.

## Requested Record Action

I request that future references treat the chat-reference-driven d_ref work as
VOID for controlling-record purposes and cite the repair artifacts instead.

The requested replacement posture is:

- Use CR004_PRECOMMIT first for the normalized `d_ref = 1` convention.
- Use the d_ref blind/source-bounded derivation as the best repair of the issue.
- Use the chain-of-events and nondisclosure audits to document why the flawed
  work chain was voided.
- Do not use the voided chat-reference premise to demand further downgrades.
- Do not convert normalized `d_ref = 1` into an absolute SI-length claim without
  a separate source and derivation.

## Non-Requests

This appeal does not request deletion of historical artifacts.

This appeal does not request restoration of absolute SI/native-substrate,
bench-scale, patent, or apparatus claims from normalized `d_ref = 1` alone.

This appeal does not request that repair audits be voided. The repair audits
remain necessary because they document how the failure happened.

## Appeal Statement

The d_ref work demanded in response to the chat-history reference was completely
unneeded as a controlling-record demand because the relevant normalized
information was already present in the repo and was not disclosed. The resulting
work chain is now VOID for controlling-record purposes due to multiple
operational failures: use of non-repo material as the practical trigger,
nondisclosure of repo-local material, defective redaction of CR004, and
overextension of CR013 underdetermination.

The audits documenting those failures, together with the d_ref blind/source-
bounded derivation, should remain as the best efforts to repair the situation.
