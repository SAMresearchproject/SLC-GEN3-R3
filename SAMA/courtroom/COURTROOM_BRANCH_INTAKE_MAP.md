## Zipper Rule

Each branch should be handled one at a time:

```text
Sean supplies README
Codex cleans encoding only as needed
Codex writes branch-local CR test
Codex runs test
Codex records result in branch README
Codex writes HASHES.txt inside the test folder
```

Root `cases/` is retired. Root `hashes/` is retained only for the original
Courtroom standard hash.

## Superseded / Contaminated Branch Folders

```text
09_PARTICLE_MASS_CHAIN -> superseded by 09a_PARTICLE_MASS_CHAIN
```

The superseded `09_PARTICLE_MASS_CHAIN` folder is preserved in place as
historical material only. New particle mass-chain Courtroom work must go into
`09a_PARTICLE_MASS_CHAIN`.

## Provenance Source Paths

The memory files are authoritative provenance/source-tracing inputs for branch
README generation, but they should not be copied into the Courtroom root:

```text
C:\VS\memory\PRIORITY_RECORD.md
C:\VS\memory\OPERATIONAL_MEMORY.md
```

Branch READMEs may cite these paths and branch-local CR manifests may hash the
specific README/test artifacts they generate. If a test directly uses one of
these files as an input, that test folder must list it explicitly in its local
input manifest.
