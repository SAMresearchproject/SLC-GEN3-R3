# Finite Particle Grammar, Starbreaker and Binding

## Conceptual abstract

This parent follows one object through two volumes. Volume II constructs a
finite matter row only after its source table, schema, address and operator
are fixed. It distinguishes the several finite surfaces by purpose, develops
mass and binding channels, and preserves carriers and containers that are not
ordinary matter. Volume III then serializes those typed objects into a finite
computation grammar. The execution does not flatten them into anonymous
numbers: exact rationals remain exact, non-row operators remain non-row, and
the W8/X1/W9 lifecycle retains its typed direction.

The complete route is

```text
typed matter surface and row grammar
→ current finite-particle catalog
→ mass and binding channels
→ carrier/container return
→ N100 computation grammar
→ SAM Language and exact program semantics
→ W8/X1/W9 lifecycle
→ Theta18 return
→ Starbreaker formation and binding readback
→ ATOM3D matter reception and Theta18 re-emission
```

This parent replaces a stale synthesis by rebuilding the route from the
current source spines, atomic records and exact result artifacts. The older
SAM_321 exemplar may suggest organization; no equation, count, status or
current claim is accepted merely because it appears there.

## 1. Ontology and type firewall

### 1.1 Matter row

A finite particle row is not identified by one number. Its identity is the
tuple

\[
\mathfrak r=(\mathcal S,\Sigma,a,\mathcal O),
\]

where (mathcal S) is the source table, (Sigma) the row schema, (a) the
typed address and (mathcal O) the acting operator. Partition, sign, charge,
depth, route combination, surface, bin and known label are meaningful only
inside this tuple.

Two rows carrying the same scalar can remain different because their schema
or operator differs. Conversely, one row can appear in more than one derived
predicate without becoming two source rows.

### 1.2 Substrate atom and lifecycle roles

The operational packet distinguishes

- `X1`: transient activator;
- `W8`: octahedral substrate atom; and
- `W9`: completed relation \(X1+W8=W9\).

All three have zero mass lift in this packet. W9 is not a second object added
beside X1 and W8; it names their completed relation. None is automatically a
matter row or tensor.

### 1.3 Carrier, container and ordinary row

Theta18 is released carrier traffic. It has no seated target row and no
retained lift fee. F81 is an aggregate face value. The A-field carrier is
transport infrastructure outside the thirteen-value full-face expression.
These roles are heterogeneous and must survive serialization.

### 1.4 State, program and history

A serialized row set is an input state space. A SAM Language program is a
typed operator on that space. A W8/X1/W9 event is an executed lifecycle. Its
append-only or quotient record is a history. Starbreaker consumes and emits
typed structures through that lifecycle; none of these objects is renamed
into another because one file contains all of them.

\[

## 5. Mass, lift and binding remain typed before serialization

### 5.1 Normalized lift by row class

For a lift-table row with native source (K) and surface debit or credit
(X), define

\[
Y=\frac XK.
\]

The row class selects the exact form. Examples include

\[
Y_{\rm color}=\operatorname{sgn}(q)\frac{|q|+D}{R},
\]

\[
Y_{\rm equal}=\frac{D+2}{R(D+1)}=\frac5{48},
\]

and

\[
Y_{\rm OCTET}=\frac{D^2+S}{DS^2}=\frac{17}{192}.
\]

An ordinary unequal pair uses

\[
Y=\operatorname{sgn}(a-b)\frac{|a-b|+D}{R^4},
\]

whereas an OCTET-involved unequal pair replaces \(D\) in the numerator by
\(D^2/R\). A single write has \(Y=0\); a no-depth support row has \(Y=1\).
For the photon carrier \(K=X=0\), \(Y\) is undefined rather than defective.

The formulas demonstrate why one global approximate lift law would be a type
error. The computational serializer must carry the row class along with the
rational value.

### 5.2 Exact asymmetry bridge

The binding child develops the registered coefficient

\[
\kappa=\frac{7117}{768}.
\]

For the declared mass- and substrate-side quantities,

\[
Q_{\rm mass}=4A\kappa,
\qquad
Q_{\rm sub}=8Z\kappa+\frac{N-Z}{8}.
\]

Using \(A=N+Z\), expand the mass side:

\[
Q_{\rm mass}=4(N+Z)\kappa=4N\kappa+4Z\kappa.
\]

Subtract the substrate side:

\[
\begin{aligned}
\Delta Q
&=4N\kappa+4Z\kappa-8Z\kappa-\frac{N-Z}{8}\\
&=4\kappa(N-Z)-\frac{N-Z}{8}\\
&=(N-Z)\left(4\kappa-\frac18\right).
\end{aligned}
\]

Insert \(\kappa=7117/768\):

\[
4\kappa-\frac18
=\frac{7117}{192}-\frac{24}{192}
=\frac{7093}{192}.
\]

Therefore

\[
\boxed{\Delta Q=(N-Z)\frac{7093}{192}}.
\]

Squaring and applying the registered normalization produces the exact
coefficient

\[
\frac{50310649}{1366464}.
\]

The route is preserved symbolically so Volume III receives exact rationals,
not decimals stripped of their origin.

## 6. Matter-to-computation serialization

### 6.1 Interface

Volume III receives typed connectors, carriers, matter and antimatter rows,
lift operators, nuclei, isotope/element rows, closure addresses and compressed
accumulation-source outputs. The serializer carries both a value and its
type:

\[
\operatorname{serialize}(x)=(\operatorname{type}(x),\operatorname{value}(x),
\operatorname{source}(x),\operatorname{operator}(x)).
\]

This is an explanatory representation of the registered contract, not a new
physical equation. It makes explicit why equality of scalar values cannot
merge two objects.

### 6.2 N100 pruning boundary

The computation basis contains 100 physical/source rows after five historical
\(p=9,g=0\) rows are excluded. Three boundaries must remain distinct:

1. A-field exclusion concerns non-row infrastructure.
2. The five-row packet exclusion changes the executable row roster.
3. X1 is a non-row lifecycle activator.

The derived W9 receipts \(X1+W8\) add neither source rows nor independent
objects. Consequently, selecting N100 does not rewrite the frozen 35-, 80-,
126-, 139- or 321-row physical/structural artifacts.

The source-native N100-to-F81 compiler audit preserves those row types and
retains the elementwise F81 join as open. The audit is a retest of the
cross-volume serialization boundary, not evidence that computation pruning
has discovered a new physical census.

## 7. SAM Language and lifecycle execution

SAM Language supplies a typed parser-to-evaluator path. A source program is
parsed under a fixed grammar, converted to the exact internal object, executed
without mutating the source definition, and serialized with state/history
separation.

The lifecycle child fixes the conceptual target before implementation:

```text
X1 activation
→ W8 substrate transaction
→ completed W9 relation
→ Theta18 carrier output or return
→ retained state and exact history receipt
```

Because W9 is the completed relation, counting X1, W8 and W9 as three
independent rows would double-count the event. Because Theta18 is output
traffic, seating it as ordinary matter would change the return operator.

## 8. Starbreaker and directional readback

Starbreaker consumes the typed grammar and lifecycle to model formation,
collapse and emitted structure. The parent does not replace its detailed
operators with a metaphor. Its required handoffs are:

1. the input roster is source-derived and finite;
2. connector, matter, carrier and container tags remain attached;
3. lifecycle events are executed in their declared order;
4. emitted carrier or source-support behavior is distinguished from the
   retained material state; and
5. binding or directional history is read from the executed structure rather
   than imposed as a row label.

The directional-history child then separates endpoint state from the route by
which it was formed. This mirrors Volume I's endpoint/road firewall at a new
technical layer: identical endpoints need not carry identical histories.
