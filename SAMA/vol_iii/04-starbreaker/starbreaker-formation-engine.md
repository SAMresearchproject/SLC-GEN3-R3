Starbreaker is a formation application with its own native grammar. It retains
2,976 ledgers, 482,112 typed atoms, seed/collapse/final stages, two event
orders, two D18 pair maps, same and reversed occurrence views, contact
incidence, record origin and constrained M126/N144/N144+d/L162 readouts. N100

substituted for this application.

The exact state ladder begins with M126 retention. Fee-exempt Theta18 provides
an independent 18-coordinate lift, so \(2^{126}\cdot2^{18}=2^{144}\). L162 is
an ambient occurrence view whose valid image still contains \(2^{144}\)
states, not \(2^{162}\) independent matter configurations. Active mismatch
coordinates travel in an N144+d sidecar rather than being promoted to another
object or capacity.

The structure-first replay detects those native quotient, fiber and readout
certificates. It reproduces the completed parent byte for byte, passes 78/78
checks and never invokes dense H14F fallback. The W9 history refinement adds a
rank-161 target-local order-history receipt, but the mode is emit-only: it may
record cross-stage memory and may not alter scheduler grouping or allocation
without a separate tested promotion.

The Courtroom evidence supplies a complete methodology chain. CR210 reconstructs
a scoped external-collapse directional-contact surface. CR211 freezes a typed
162-slot particle-ledger interface while leaving address-to-template incidence
null. CR005c identifies why stage ordering cannot be promoted to physical

source bridge. CR005e stops on a numerical trace-residue gate; CR005f freezes
one exact trace-free correction; CR005g runs the unchanged morphology design
and records the boundary that no stable Starbreaker/CCSN morphology match
cleared the gates. CR005h constructs a complete per-carrier ledger but fails
three controls; CR005i corrects only those controls, independently replays all
96 scenarios and 53,568 carriers, adopts the byte-identical ledger and leaves
CR005h immutable.

## 1. Opening question and conceptual picture

The governing question is:

> How does Starbreaker carry a source-native formation history from typed
> ledgers through exact state accounting, directional contact, continuous
> source construction and controlled application readouts without replacing
> its grammar, erasing failed tests or promoting dimensionless receipts into
> physical observables?

The application picture is

```text
Starbreaker ledgers and typed atoms
  -> seed / collapse / final formation stages
  -> lexicographic and reverse event orders
  -> exact M126 retention
  -> fee-exempt Theta18 lift to N144
  -> optional active mismatch sidecar N144+d
  -> constrained L162 occurrence views
  -> emit-only W9 rank-161 history
  -> dimensionless source/application bridges

```

The route is layered. A state count is not a waveform. A source quadrupole is
not strain. A carrier with positive source influence is not the substance
transported by a gravitational wave. Keeping those types separate is what
allows the exact and exploratory work to accumulate safely.
