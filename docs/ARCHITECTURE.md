# SLC architecture: portable R3 and installed R4

The portable SLC-GEN3-R3 release is one learning and executing runtime. Its state includes the
mathematical execution, reusable source support, actual observations and ordered
history. The CE binds that runtime to scoped applications.

## State and source execution

Programs operate on native SAM Writes and source-defined objects. Signed state,
phase, barriers, complete inverse alternatives and observation ties remain part
of the computational record. A learned relation is useful through a declared
source-to-operation mapping: matching support can be applied directly, while
new support is admitted with its source identity. An unknown imported object
requires semantic admission before it supplies a source relation.

## Exact logarithmic accounts

For admitted positive quantities along a source history, rises contribute to U
and falls to D; V=U+D and L=U−D. M keeps the maximum relative to the original
reference and every occurrence attaining it. The representation retains exact
ratio arguments, so cancellation, append and adjacent composition remain exact.
Zero, negative and missing inputs produce explicit domain/gap handling. The
history retains its states, events and references alongside the account.

For example, the positive path 1→2→1 has equal rise and fall, net logarithmic
change zero, and positive variation. The source path and its two events remain
available after reading that summary. The public tests check cancellation,
append and all maximizing ties directly.

## Observation and recovery

Actual supplied observations update acquired branches. Complete alternatives
and ties remain represented. The durable store commits execution, acquired
knowledge and exact accounts under one authenticated root; a fresh process can
recover that root and continue the source execution. Upstream multi-host
replication transfers missing immutable chunks. The portable package provides
local durable recovery; configured remote replication is a separate deployment.
