# SLC-GEN3-R3

One learning and executing runtime owns source state, acquired relations,
supported compositions, actual observation encounters, complete histories and
exact logarithmic accounts. The selected engine is `gen3_runtime.py`. GEN2
operation names and the Q3 compatibility import route into this same runtime.

`GEN3_EXECUTE` accepts a native `GEN2_RUN` payload. Unseen source-scoped event
support is acquired during execution; known support executes directly. A new
program can compose known relations without having been seen as a whole.
Returned `r3` data identifies the complete history and exact accumulation.
Omitting `initial` continues the current state and contract. Each call retains
its original reference account; the journal preserves order between calls.

For positive source E, delta=ln(E_after/E_before). U accumulates rises, D fall
magnitudes, V=U+D, and L=U-D=ln(E_final/E_initial). M is the maximum excursion
from the original reference, with every maximizing occurrence retained. Logs
use `{"type":"EXACT_LOG_POSITIVE_RATIONAL","argument":"5/3","sign":1}`.
Arguments stay unfactored; the whole ratio determines sign. FLINT accelerates
exact arithmetic where installed; Fraction produces identical exact values.
Zero, negative and missing action retain gaps and positive segments. Full
phase, signed state, barriers and source events remain distinct from V.

`GEN3_LOG_OPEN` takes `account`, `quantity`, `source_binding`, `points`, `edges`.
Points have unique `id`, full `state`, exact `action` and optional availability
`status`. Edges have `id`, adjacent `before`/`after` IDs and explicit `event`.
`GEN3_LOG_APPEND` takes `account` and only new connecting points/edges.
`GEN3_READOUT` and `GEN3_HISTORY_EXPORT` take `{"account":"name"}`.
`GEN3_LOG_COMPOSE` takes a new `account` plus adjacent `left`/`right` accounts;
it composes positive segments algebraically while retaining shared chunk custody.
`GEN3_LOG_IMPORT` uses the same semantic source admission as open. A resealed
edited summary is never accepted as a substitute for source admission.

The 192 acquired native relations load into execution. The 85-node observation
graph and original sequential/bundle/tau memories remain installed.
`GEN3_MEMORY_START` takes `memory`, new `encounter` and optional `node`.
`GEN3_MEMORY_APPLY` takes `encounter`, actual `observation` and source `evidence`.
All matching complete members and choice ties remain. A remembered branch
never fabricates a measurement. `GEN3_MEMORY_NODE` exposes an acquired node.
Native inverse/observation calls acquire and reuse inference support in this
same warm runtime; unsupported branches remain explicit.

Managed DomainSession consumers attach `R3_STATE` inside the session directory.
Successful changing calls commit immutable changed objects and one atomic root
covering state, knowledge and readouts. `GEN3_CHECKPOINT` takes `{}`.
Current-generation reopening authenticates the snapshot and complete closure;
unknown imports require semantic reconstruction. The local custody key is
separate from exported objects. `GEN3_REPLICATE` takes `{}` and transfers only
missing objects to lilhelper. Replicated status requires a durable T500
acknowledgement of the same complete root. Prior checkpoints remain preserved.

Save a job such as this and run `./r3 run --job job.json`:

```json
{"domain":"MATTER_SEARCH","objective":"Execute and learn a native history","operations":[{"operation":"GEN3_EXECUTE","payload":{"initial":[0,0,0],"program":["W1+","W7-"]},"purpose":"Execute the declared signed Writes and retain exact source readouts"},{"operation":"GEN3_CHECKPOINT","payload":{},"purpose":"Commit execution, knowledge and readouts together"}]}
```

`--session PATH` reopens durable state. `./gen3` is the same entrypoint;
`./r3 legacy ...` preserves the former lesson interface on the global runtime.
Python consumers use `.venv-r3/bin/python`. For substantial custom scripts,
use `CURRENT_REVISION/engines/SLC/gen3/resources.py run -- COMMAND`.

The launcher samples prelaunch availability and enforces shared 70% local /
90% helper CPU and RAM budgets in `sam-r3.slice`. The i9 owns state; P cores
serve the coordinator and E cores serve suitable parallel/I/O work. Ryzen
executes independent batches beside the T500. One locked 780M lane executes
qualified exact packed transition/contraction kernels. Native batch pools
select measured worker schedules, physical cores first; numerical library
threads default to one. Children share the aggregate budget. Memory follows
demand, T500 writes preserve 20 GiB free, and maintenance cooperates with the
same run lock. No RAM disk or new partition is allocated.

The exact Write foundation, Q3 quality, signed quantities, complete inverses,
phase/winding, motion, domain models and original acquired artifacts remain
bound components. Their historical names do not select another global engine.
